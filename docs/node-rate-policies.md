# 节点场景倍率策略

动态倍率在节点管理页面内配置：点击搜索框旁的「操作 → 动态倍率设置」，即可展开时段规则、全局带宽参数、场景策略和倍率台账。侧栏不再提供独立的动态倍率页面；旧地址会跳转到节点管理并展开设置。

节点管理的「操作 → 批量设置倍率策略」支持三种模式：

| 模式 | 带宽计数范围 | 计费行为 |
| --- | --- | --- |
| 继承全局策略 | 同一订阅使用所有继承全局的节点 | 使用全局带宽参数 |
| 绑定场景策略 | 同一订阅使用同一个策略下的节点 | 使用该场景的独立参数 |
| 不参与带宽动态加倍 | 不采集带宽判定样本 | 带宽动态因子固定为 1 |

实际扣流量倍率 = 节点基础倍率 × 时段倍率 × 当前场景的带宽动态倍率。
全局和场景的带宽动态倍率只取其中一个。全局开关仅控制继承全局的节点，各场景独立启停。
关闭带宽动态加倍后，基础倍率和时段倍率仍然生效。

## 使用

1. 在节点管理的「操作 → 动态倍率设置」中，新建场景策略，例如普通线路、专线，设置阈值、突发豁免时长、持续门槛、叠加倍率和回落步长。不勾选节点也能管理设置。
2. 勾选节点（可使用 ID 范围选择），点击策略行的「应用到所选节点」，或打开「操作 → 批量设置倍率策略」。配置和批量绑定都在节点管理内完成，展开或收起设置会保留已选节点。
3. 选择策略模式，预览逐节点改动，再确认应用。保存后会重新读取并核对绑定。
4. 节点列表显示绑定策略；动态倍率台账可按场景和账号搜索，查看具体订阅的各节点倍率构成。

同一订阅在同一场景内切换节点会保留计数，切到另一场景后使用另一份计数。
一个账号的不同订阅分别计数。旧版没有订阅的用户继续使用原用户 ID 作为计费身份。
同一策略内多个节点的原始上行、下行流量会汇总成该订阅的分钟平均速率；节点总负载不参与判定。
多个父子节点共用一份上报时，应为实际向面板上报流量的节点设置策略。

修改策略会更新版本并重新计数，旧版本的倍率和排队样本不用于新规则。
保存配置后，后续上报会读取新配置；带宽判定由每分钟任务更新，已受理的流量按受理时取得的倍率入账。
停用的策略仍采样供观察，重新启用后从新版本开始计数。
删除策略前需要解除绑定；节点 ID 变更会迁移绑定，删除节点会清理绑定。
新建和复制的节点默认继承全局，可在发布前批量绑定需要的策略。

## 升级与运行

按项目原有更新流程部署即可。新增幂等迁移 `rate_policy_schema` 创建策略、节点绑定、场景状态三张表；现有时段规则和全局参数保留。
手工更新时，在项目目录使用运行站点的 PHP 执行：

```sh
php artisan v2board:update
php scripts/patch-admin-rate.php
```

代码部署后按现有进程管理方式重新加载 Webman 和队列进程，使它们使用新代码。`update.sh` 已包含这一步。
日后在后台保存策略、绑定和时段规则，不需要再次重启进程。

确保每分钟的 `artisan schedule:run` 正常运行；其中 `rate:tick` 发布计费快照并推进状态。
首次升级后的场景计数从零开始，第一次定时任务会初始化运行配置；也可执行一次 `php artisan rate:tick` 初始化。
旧版队列任务保留当时计算的扣量倍率，其缺少场景信息的采样不会混入新计数。
带宽倍率缓存有效期为 180 秒；采样任务中断后，过期的带宽倍率回落为 1，避免长时间沿用旧判定。

```sh
php artisan rate:explain 123
php artisan rate:explain 123 --node-user-id=2000000123
```

第二条指定该账号下某个订阅的计费标识；`--at` 只用于检查时段规则匹配，不回放历史带宽状态。

后端的 `RatePolicyTest` 覆盖跨节点累计、跨场景和跨订阅隔离、基础/时段倍率叠加、停用即时生效、旧样本版本隔离、并发预览冲突、事务回滚、ID 迁移、缓存过期、迁移未完成时拒绝写入，以及 Redis 故障后的节点绑定清理。
`admin-rate-page.test.cjs` 与 `admin-server-batch-operations.test.cjs` 验证策略表单、批量预览、保存和重新读取核对。
