# 管理员角色与 4A 安全审计

本次升级将后台身份认证、角色授权、账号管理、操作审计集中管理。权限以服务端每次读取的用户记录为准，菜单和业务 JavaScript 同时按角色提供。

## 权限范围

| 角色 | 可用业务 |
| --- | --- |
| 超级管理员 `super` | 全站业务、管理员角色、安全审计；仅用户 ID 1 的现有管理员 |
| 运维管理员 `operations` | 系统/支付/主题设置，节点/权限组/路由及节点内动态倍率，风控 |
| 财务管理员 `finance` | 订单查询、分配、修改、取消、支付确认、补单 |
| 客服管理员 `support` | 工单列表、阅读、回复；不能关闭工单或管理用户 |
| 运营管理员 `marketing` | 订阅套餐、优惠券、礼品卡、签到与娱乐 |

所有角色均可管理自己的密码、二步验证和登录会话。未列出的业务默认仅超级管理员可用。新控制器方法不会自动继承普通管理员权限，需要在 `AdminAccessService` 中明确授权。

财务页面通过订单接口取得必要的用户 ID/邮箱，以及只读套餐价格选项；运营页面取得必要的权限组 ID/名称与货币设置，不开放完整用户管理、节点管理或系统配置接口。

运维不能修改管理员角色、管理员二步验证强制策略及主题的自定义 HTML/脚本注入字段。脚本与后台同域运行，允许普通角色植入脚本会破坏角色隔离；普通主题设置仍可修改。管理员账号停用 Telegram 免密链接、Telegram 找回密码和第三方 OAuth 登录入口，保留密码与二步验证登录，避免通过运维可配置的第三方服务取得高权限账号。

旧系统配置接口不能绕过运营权限修改签到娱乐参数；Telegram 游戏规则管理也只允许超级管理员/运营管理员，并记录修改。Telegram 业务通知按角色投递：订单给超级管理员/财务，节点与风控给超级管理员/运维，工单给超级管理员/客服。未分配角色的旧管理员不接收这些通知。

## 升级与首次分配

1. 备份数据库、配置和审计密钥。确认 `v2_user.id=1` 是未停用的现有管理员；若不满足，升级会停止，不会把普通用户自动提权。
2. 首次升级应在服务器入口暂时限制后台访问，并暂停旧队列进程。将 PHP 代码、模板、构建清单、公开登录资源和 `resources/admin/build/` 五份资源作为同一版本发布。
3. 使用迁移账号运行以下命令。它需要建表、加列及创建触发器权限：

   ```sh
   php scripts/check-admin-security.php
   php artisan v2board:update
   php artisan optimize:clear
   ```

   MySQL/MariaDB 开启 binlog 且 `log_bin_trust_function_creators=OFF` 时，普通账号
   创建触发器会报 1419。`update.sh` 已支持停服前检查及迁移期间临时兼容设置；
   管理员凭据文件配置和恢复办法见 [数据库触发器部署兼容](deployment-db-triggers.md)。

4. 重启 Webman、PHP 常驻进程和队列工作进程，使所有入口都加载新权限代码。现有 `update.sh` 已集成构建校验、迁移、Horizon 退出重启与 Webman 重启；首次升级仍应确保没有旧进程在迁移期间处理后台任务。此后分配/撤销角色无需重启。
5. 以 ID 1 重新登录后台，在「用户管理 → 编辑用户」的「管理员身份」选择普通用户或四种管理员角色之一，与用户资料一起提交。选择普通用户即撤销后台权限；ID 1 显示为只读的超级管理员，不能另设超级管理员。
6. 抽查各角色菜单与拒绝访问结果，并在「安全审计」校验记录完整性。

首次迁移使旧管理员/旧客服会话失效，非 ID 1 账号处于待分配状态。旧账号不会默认获得运维或其他权限；重复执行升级不会重置已分配角色。角色变更递增 `admin_version`，用户资料与身份在同一事务中保存，提交成功后撤销旧会话；保存失败会回滚，未改身份不会撤销会话。后台单条和批量删除、停用操作均保护 ID 1。

这是代码升级后的部署步骤；开发测试不会连接生产库为真实账号提权。

## 前端构建与资源隔离

当前仓库以原有 Umi 编译资源为基础，完整原始前端工程不在仓库内。保留的模块放在 `resources/admin/legacy/`，通过 AST 处理路由、模型、组件依赖，再生成各角色的可达模块集合；构建遇到未知结构或越权页面依赖会报错。

```sh
npm ci --prefix scripts --ignore-scripts
npm run build --prefix scripts
php scripts/check-admin-security.php
node --test scripts/tests/admin-security.test.cjs
```

修改已有节点/倍率补丁后必须重新执行构建，并一同提交清单和生成资源。生产发布使用已构建产物，不要求服务器安装 Node。新增维护页面源码位于 `scripts/admin-security/`。

Web 服务器根目录必须为 `public/`。不要通过别名、静态资源规则、软链接或 CDN 暴露 `resources/`、`scripts/` 或项目根目录。删除旧公开资源 `assets/admin/umi.js`、`vendors.async.js`、`components.async.js` 及其旧副本、source map，并清理 CDN 缓存；构建校验会拒绝三个原文件重新出现在公开目录中。

未登录只加载公开登录代码。登录后凭 Authorization 请求 `/security/asset`，服务端依据当前角色选择资源，忽略客户端提交的角色名称。脚本响应使用 `private, no-cache, must-revalidate`、`Vary: Authorization` 和内容 ETag：浏览器每次复用脚本前仍需服务端检查当前会话及角色，内容未变时返回 304，避免重复下载数 MB 的脚本。权限和业务接口继续使用 `no-store`；CDN 不得缓存受保护接口。浏览器端切换身份会重新加载页面。

后台 HTML 自带静态侧栏、顶栏和内容占位，必要样式直接内联，完整样式表异步下载。权限确认和脚本加载期间保留这个框架，React 与样式都就绪后直接替换，不再隐藏加载内容留下空白，也不显示全屏转圈动画。缓存的菜单仅作为不可交互的文字占位，不包含业务数据，受保护代码仍在服务端验证当前权限后执行。

浏览器由使用者控制，无法保证禁止 F12 或撤回此前已下载的代码。生产页面提供快捷键阻止，但安全边界始终是服务端拒绝越权接口、拒绝发送未授权业务模块。开发环境 `local/testing` 自动豁免快捷键阻止；部署配置 `ADMIN_DEBUG_EXEMPT=true` 可临时豁免，该配置**不会豁免权限或审计**。

## 留痕与不可删除的范围

- 后台请求（包括读取、失败和拒绝）、管理员登录、角色变更、自身安全设置和 Telegram 工单回复都记录审计。管理员通过用户端调用自身安全接口也会留痕。
- 新记录将中文操作说明写入签名载荷，例如「修改用户资料」「批量修改节点名称」「修改管理员身份：普通用户 → 运维管理员」。界面使用中文操作、角色和结果，并支持按中文操作内容查询；旧记录在读取时转换显示，不改写原始载荷或哈希链。事件代码仍保留用于接口精确查询和完整性校验。
- 管理员发起的队列任务携带操作者、角色版本和关联请求 ID，执行前重新检查权限，记录开始、修改和结果；角色已变更时停止执行。旧版任务没有这些元数据，首次升级须先处置旧队列。
- Eloquent 写入保留脱敏后的前后值，批量修改分段记录；配置文件和倍率配置另有快照。原生 SQL 只记表名和操作，不记录可能包含密钥的绑定值。新增原生 SQL 写法需补充对应快照，不能依赖它自动生成逐行前后值。
- 密码、令牌、密钥、恢复码、消息正文及自定义 HTML 等被脱敏，审计界面不能用来恢复这些内容。大字段记录摘要；通用参数集合最多记录 1000 项并标明截断，业务模型变更按 100 项分段。
- 写操作先持久化意图，再执行数据库事务；事务内完成审计失败会回滚 SQL 修改。文件、邮件、Redis、远程接口等外部效果不能随 SQL 回滚，需结合意图与失败记录复核。队列也记录执行意图，进程中断可能留下 pending 记录。
- 异步队列配置 `after_commit=true`。Laravel 8 的 sync 驱动仍立即执行：同步任务的数据库写入随外层事务回滚，已发出的邮件等外部效果不能撤回。生产建议使用 Redis/数据库队列。

审计使用独立表 `v2_admin_audit`，后台没有修改、删除、清空接口，现有日志清理任务不处理此表。SQLite/MySQL/MariaDB 触发器拒绝 UPDATE/DELETE；连续序号、前向哈希和 HMAC 验证可发现断链、字段篡改和尾部缺失。超级管理员仅能查询、筛选、导出、校验。

应用内不可删除不等于主机/数据库 root 不可删除。DROP/TRUNCATE、删除触发器、恢复旧数据库或同时窃取签名密钥不属于应用能够阻止的范围。生产应分离迁移账号和运行账号，运行账号对审计记录表仅授予 SELECT/INSERT，对链头授予 SELECT/INSERT/UPDATE，且没有 DDL、触发器管理权限。其余业务表权限按业务单独配置。MySQL 的触发器定义者必须为持续存在且权限合适的账号。

## 密钥与异地不可变归档

`ADMIN_AUDIT_KEY` 用于审计 HMAC；未设置时兼容使用 `APP_KEY`。建议在首次迁移前配置独立随机密钥并离线备份，迁移后保持稳定；更换实际签名密钥会导致旧链无法通过校验，当前未提供自动轮换机制。

`ADMIN_AUDIT_ARCHIVE_DISK` 指向 `config/filesystems.php` 中配置的 Laravel Storage 磁盘。归档命令先验证链，将 JSONL 记录与链检查点写入独立、随机命名的私有对象，记录成功或失败，**始终保留本地原始记录**：

```sh
php artisan security:audit-archive --after=0 --limit=10000
# 下次使用上次输出的最后序号继续导出
php artisan security:audit-archive --after=10000 --limit=10000
```

`after` 必须使用命令实际输出的最后序号。由部署方调度并保存成功检查点；失败不要前移检查点。普通管理员不能通过后台配置该磁盘或执行归档。归档前完整链校验会随日志量增长耗时，建议在独立调度窗口执行。

磁盘本身不会自动变成不可变存储。部署方必须在独立控制的对象存储启用版本保留、Object Lock/WORM 及默认保留策略，使用只能新建对象、不能删除或缩短保留期的凭据；归档命令不创建存储桶、不配置对象锁。对象锁不应只依赖单个请求头。需安装所选 Laravel 文件系统驱动并验证实际云端策略；本地磁盘适合功能测试，不能提供主机外的防删保证。

## 验证与已知限制

详细业务审计的实现、全部入口清单及数据库验收见 [详细审计交付与覆盖清单](admin-audit-detail-coverage.md)。新记录包含中文对象、字段前后值、真实业务结果、批量逐项明细和任务关联；原始历史链保持不变。升级需清除旧配置缓存并重启常驻进程，使新增的 `config/admin_audit.php` 生效。

```sh
php vendor/bin/phpunit tests/Feature/AdminSecurityTest.php
node --test scripts/tests/admin-security.test.cjs
# 已安装 Playwright/Chromium 后；也可用 PLAYWRIGHT_MODULE 指向现有包
node scripts/tests/admin-security.browser.cjs
```

测试覆盖五角色菜单和资源、用户编辑中的身份选择、直接 API 越权、旧 staff 入口、唯一超级管理员、角色撤销生效、审计防改删、中文操作记录与历史查询、事务回滚、队列上下文、登录失败、自身安全操作、导出归档、主题注入保护和财务最小用户信息。浏览器测试使用模拟 API，真实权限由 PHP 接口测试验证。

本地已验证 SQLite 和隔离 MariaDB 11.4.5 的详细审计路径；数据库测试范围和结果见上述交付清单。独立存储的对象锁仍需在部署环境验收。此处“4A”描述本项目集成能力，不代表取得任何认证或已连接外部堡垒机。

全量 PHP 回归还包含改动前已存在的失败：AdminTelegramUnbind 的语言预期、ExternalNodeRender 的原生 header 与响应序列化断言、ExternalSubscription 的 HTTP 错误文本预期，以及 PlanContentSanitizer 的非特性 JSON 转义。已在升级前的 `9a7b4b01` 独立检出中复现，不应将全量回归宣称为全部通过。

## 回退

不要直接回退到只检查 `is_admin` 的旧版并开放后台：新角色都带有该兼容标记，旧代码会给予其完整后台权限。优先保留新权限/审计层做前向修复。

确需版本回退时，先关闭外部后台入口并暂停相关队列，归档和备份审计，再由持有数据库权限的维护者把非 ID 1 的管理员/客服权限置为停用并清除其会话，然后才切换旧代码。保留角色字段、审计表、链头和密钥，不删除审计记录，不执行破坏性的 down migration。恢复对外服务前核实只有 ID 1 可进入旧后台；重新升级后仍需逐个恢复角色。
